# Task hub

Беклог великих задач для агентів і людей: фічі, рефактори, UX-пачки. Дрібні правки сюди не
потрапляють — їх роблять одразу. Кожна задача — окремий файл, який можна віддати агенту як бриф.

## Як користуватись

Найпростіше — скіл `/take-task` (`.claude/skills/take-task/SKILL.md`). Він сам вибирає наступну задачу
за пріоритетом (або бере вказану, `/take-task T-007`), оновлює статуси, питає погодження і доводить
задачу до кінця. Вручну процес такий:

- **Взяти задачу:** відкрий файл, постав `status: in-progress`, працюй у своїй гілці.
  Перед стартом прочитай розділи PRD і правила з `.agents/rules/`, на які посилається задача.
- **Закрити задачу:** усі пункти «Критерії готовності» виконані, перевірки з `safe-code.md §7`
  пройшли, `status: done`, у таблиці нижче оновлений статус. Файл не видаляємо — це історія рішень.
- **Нова задача:** скопіюй [`_TEMPLATE.md`](_TEMPLATE.md), дай наступний вільний id, додай рядок у
  таблицю. Опис пишемо людською мовою: спочатку *навіщо гравцю/бізнесу*, потім *що робити*.
- **Потребує погодження:** якщо в задачі стоїть `needs-approval`, агент зупиняється перед цим
  кроком і питає користувача (нові залежності, мережа, зміна продуктового скоупу).

## Пріоритети

| Пріоритет | Значення |
| --- | --- |
| **P0** | Ламає довіру, реліз або правила продукту. Робимо першим. |
| **P1** | Помітно б'є по утриманню, зрозумілості чи якості. Наступний спринт. |
| **P2** | Покращення, яке варто зробити, але гра живе і без нього. |
| **P3** | Ідея / дослідження. Беремо, коли P0–P2 порожні. |

Розмір: **S** ≤ пів дня, **M** 1–2 дні, **L** 3+ днів (такі краще ділити на етапи всередині файлу).

Статуси: `todo` · `in-progress` · `blocked` · `done` · `superseded` (задачу розібрано по інших, файл
пояснює куди).
