# T-021 · Перевіряти гру за хвилини, а не за години

## Навіщо (людською мовою)
Щоб перевірити ранг CEO або престиж, зараз треба грати 2–3 години. Debug-меню («×100 часу», «дати
ресурси», «стрибнути на ранг») робить ручні перевірки й плейтести швидкими. А CI ловить зламаний баланс
і тести до збірки APK — PRD ставить це гейтом фази 0.

## Що бачимо зараз
- Симуляція балансу є: `src/features/purchase-skill/__tests__/phaseBalance.test.ts` (±20% від цілей).
- Немає debug-меню, немає CI (`.github/workflows` відсутній).

## Що зробити
1. **Debug-меню**, доступне лише в `__DEV__` (у release-збірці коду немає або він недосяжний):
   множник швидкості часу (×1/×10/×100) у game loop, видати ресурси, встановити ранг (через валідні
   дії моделі, не обхід правил), скинути онбординг, показати сейв JSON. Відкривається жестом або
   прихованою кнопкою в налаштуваннях.
2. **Звіт часу до рангів:** скрипт `npm run balance:report`, що запускає симуляцію і пише CSV/таблицю
   (ранг, хвилини, ціль, відхилення) — для рішень по балансу.
3. **CI після погодження:** workflow `ts:check` + `npm test` (включно з симуляцією балансу) + web export
   на кожен push/PR. Кеш npm. Без секретів.
4. Тести: множник часу клампиться (safe-code §2), debug-дії недоступні в production-режимі.

## Критерії готовності
- [ ] У dev-збірці можна дійти до рангу CEO за кілька хвилин через ×100.
- [ ] Release-бандл не містить debug-меню (перевірено пошуком у web export або тестом).
- [ ] `npm run balance:report` друкує таблицю часу до кожного рангу.
- [ ] CI зелений на поточному `main` (після погодження).
- [ ] `npm run ts:check`, `npm test`, web export пройшли.

## Поза скоупом
Remote config і A/B (E16), термінал із чит-командами як пасхалка для гравців (окрема ідея).

## Де в коді
`entities/game-loop` (множник часу), новий `features/dev-tools` або `widgets/debug-menu`,
`package.json` scripts, `.github/workflows/`.

## Ризики і відкриті питання
- Множник часу має йти через той самий `tick` з клампом, інакше можна обійти safe-code §2.
