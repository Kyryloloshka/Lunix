# T-024 · Інциденти: гра питає, як ти вчиниш

## Навіщо (людською мовою)
Кожен розробник знає «впав прод у п'ятницю ввечері». Інцидент — коротка історія з вибором і видимим
наслідком: хотфікс (швидко, але +стрес), rollback (безпечно, але −дохід на хвилину), ігнор (нічого
зараз, але техборг росте). Це дає автономію і гумор — головний диференціатор гри.

## Що зробити
1. **Реєстр інцидентів** (дані, i18n-ключі, пародійні назви — `parodyContent.test.ts`): ≥ 10 інцидентів,
   прив'язаних до фаз (навчання: «дедлайн курсової», робота: «прод упав», вплив: «конфлікт у команді»).
   Кожен має ≥ 2 вибори з наслідками через загальний `Effect` (ресурс ±, стрес ±, тимчасовий множник,
   техборг).
2. **Техборг** як тимчасовий дебаф (наприклад −X% доходу Роботи, спадає з часом або закривається
   вибором у наступному інциденті). Якщо зберігається — `SAVE_VERSION`++ і міграція.
3. Поява через планувальник з T-023 (не частіше ніж раз на N хв, не під час інтро/модалок), ніколи не
   блокує гру; якщо гравець ігнорує картку — застосовується дефолтний вибір через таймаут без покарання
   понад описане.
4. Наслідки видно до вибору (етичне правило PRD §4: жодних прихованих шансів).
5. Події `incident_shown`, `incident_resolved` (choice) — для ачівок T-025.

## Критерії готовності
- [ ] ≥ 10 інцидентів, кожен з ≥ 2 виборами і видимими наслідками (тест реєстру).
- [ ] Наслідки застосовуються моделлю рівно один раз (тести).
- [ ] Тексти uk/en/es, проходять перевірки локалей і пародійних назв.
- [ ] `npm run ts:check`, `npm test`, web export пройшли.

## Поза скоупом
