# T-010 · Лідерборд дає наступну ціль

## Навіщо (людською мовою)
Лідерборд зараз — статичний список, де гравець на 10-му місці з $13 проти $100B у лідера. Розрив
демотивує, а найцікавіша інформація — «кого я обжену наступним і скільки бракує» — не показана.

## Що бачимо зараз
- Рядок гравця: «ВИ (ВИ)» + бейдж «ВИ» — тричі одне й те саме (`leaderboard.playerName` з `{label}`).
- NPC-статки статичні (PRD §2: «статичний список»).
- Іконка гравця — `bolt`, як у Flow та Influence.

## Що зробити
1. Над списком — картка «Наступна ціль: обігнати Петю Джуна · ще $11.9K» з прогрес-баром.
2. Анімація зміни місця, коли гравець когось обганяє (з reduced motion — без руху).
3. Рядок гравця: ім'я гравця (дефолт «Ви») + один бейдж.
4. NPC повільно ростуть детерміновано від сейву (seeded), щоб топ жив, але ніколи не був недосяжним
   поблизу гравця. Чиста функція з тестами. Дисклеймер «симуляція» лишається.

## Критерії готовності
- [x] Видно наступного суперника і розрив; тест на вибір суперника (включно з 1-м місцем і > 1e308).
- [x] «Ви» показано один раз.
- [x] Ріст NPC детермінований: однаковий сейв → однакові числа.
- [x] ts:check, test, web export пройшли.

## Поза скоупом
Реальний лідерборд (E20), ліги.

## Ризики і відкриті питання
Після T-016 у фазі навчання Capital = 0. Треба вирішити, за чим рахувати місце (наприклад загальний
«кар'єрний рейтинг» замість Capital), або відкривати вкладку «Топ» лише з першою зарплатою.
Не розкривати приховані ранги NPC-ролями (T-008).

## Де в коді
`widgets/simulated-leaderboard`; генерація NPC — у `entities/` (нова модель), не у віджеті.
Залежить від T-001 (імена NPC).

## Прогрес
- 2026-10-25 (гілка `task/T-010-leaderboard-rivalry`):
  - Чиста модель `widgets/simulated-leaderboard/model/standings.ts` (NPC-список уже живе у віджеті після T-001,
    тож модель поруч, без нового entity): `buildStandings` (сортування через Decimal `compareTo`, гравець рівно
    один раз, при нічиїй гравець нижче — обігнати = мати строго більше), `selectRival` (NPC одразу над гравцем,
    розрив і прогрес `player / rival` через Decimal `divide`; `null` на 1-му місці).
  - Ріст NPC: `capital = base · (1 + P)^α`, де P — `totalCapitalEarned` гравця (вже є в сейві), α ∈ [0.02, 0.08]
    детерміновано з id NPC (FNV-1a). Рахується в log10-просторі, коректно після 1e308. Оскільки α < 1, кожен NPC
    росте строго повільніше за гравця — розрив до сусіда тільки скорочується. SAVE_VERSION не змінювався.
  - UI: картка «Наступна ціль: обігнати X · ще $Y» з прогрес-баром (або «Ви лідер симуляції»); рядок гравця —
    ім'я «Ви» без дубля-бейджа, іконка `trend` замість `bolt`; при зміні місця рядок гравця і картка
    перемонтовуються через `FadeSlideIn` (під reduced motion — лише fade). Дисклеймер «симуляція» лишився.
  - Нові ключі i18n (uk/en/es, лише додані): `playerDefaultName`, `rivalEyebrow`, `rivalTarget`, `rivalGap`,
    `rivalTop`, `rivalTopHint`, `rivalA11y`. Старі `you`/`playerName` більше не використовуються (не видалені).
  - Тести: `widgets/simulated-leaderboard/__tests__/standings.test.ts` (вибір суперника, 1-ше місце, > 1e308,
    детермінізм, «Ви» один раз, NPC не відриваються). ts:check, npm test (198), web export — пройшли.
  - Відкрите питання: місце рахується за lifetime Capital. У фазі навчання (Capital = 0) гравець останній, ціль —
    найнижчий NPC. Чи переходити на «кар'єрний рейтинг» або ховати вкладку до першої зарплати — рішення за власником.
    Ім'я гравця поки фіксоване («Ви»), налаштування імені немає.
