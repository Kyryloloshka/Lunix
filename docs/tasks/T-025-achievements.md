# T-025 · Колекція досягнень

## Навіщо (людською мовою)
Ачівки дають довгу ціль поверх рангів: «купи 100 рівнів Reakt», «тапни 10 000 разів», «пройди
інцидент, не підвищивши стрес». Силуети невідкритих тягнуть повертатись (Зейгарнік), а +1% доходу за
кожну робить колекцію корисною. PRD: ≥ 100 до MVP, усі умови — декларативні дані.

## Що зробити
### Етап 1 — Рушій і реєстр (M)
1. Реєстр ачівок у `entities/achievement`: `id`, категорія, декларативна `Condition` (лічильник події,
   поріг ресурсу/рівня/рангу, комбінація), `hidden` для shadow-ачівок, i18n-ключі.
2. Перевірка умов — підписка на шину подій T-022 + лічильники (тапи, крити, покупки…), без опитування
   кожного кадру. Відкриття емітить `achievement_unlocked`.
3. Бонус: `income × (1 + 0.01 · achievements)` у тій самій формулі доходу (PRD §5) — і в прев'ю T-017.
4. Сейв: відкриті ачівки й лічильники, `SAVE_VERSION`++ + міграція + тест. Ачівки переживають престиж (T-026).
5. Тести: валідатор реєстру (унікальні id, умови посилаються на наявні навички/ранги), кожна категорія умов.
### Етап 2 — Контент і UI (M)
6. ≥ 100 ачівок (пародійні назви, гумор), з них ≥ 10 shadow.
7. Вкладка/екран «Стікербук»: сітка з силуетами невідкритих (shadow — «???» без умови), прогрес
   «N / M», тост при відкритті (motion T-015, reduced motion).
8. Баланс: симуляція з урахуванням бонусу ачівок; темп у межах ±20%.

## Критерії готовності
- [ ] ≥ 100 ачівок, усі умови декларативні (тест реєстру).
- [ ] Відкриття рівно один раз, переживає перезапуск і престиж (тести).
- [ ] Бонус +1% видно в HUD/довідці і враховано в доході та прев'ю.
- [ ] `npm run ts:check`, `npm test`, web export пройшли.
